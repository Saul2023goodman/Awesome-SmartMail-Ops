# v3.8.53 — Time planning first

## Problem
The dispatch header still presented `优先轮次 · 可选` as the primary button while `时间规则` was secondary. This inverted the actual workflow: priority is optional metadata, while time planning is the user's main task.

## Fix
- Dispatch now exposes one primary action: **时间规划**.
- Removed the separate top-level priority entry.
- The time-planning dialog now contains a compact **同校优先级（可选）** constraint card.
- The card summarizes how many selected messages have R1/R2… and how many schools are affected.
- Users can enter the roster priority editor from time planning and return directly to time planning after editing.
- No priority data remains a normal state and never blocks scheduling.
- User-facing wording now emphasizes **同校优先级** rather than making it look like a scheduling round.

## Flow
`安排本次邮件 → 时间规划 → (optional 同校优先级) → 应用排期 → 网易执行`

R1/R2… only constrain within-school ordering. Calendar cycles/dates remain generated by the scheduling rules.
