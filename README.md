# NetEase Mail Draft Assistant v2.5 · Mail Status Board

v2.5 保留原有导入、识别、附件、总名单、查重、排期、联系人和草稿执行逻辑，重点把邮件审阅重构为 **邮件状态板 + 单封处理弹窗**：自动通过邮件只需扫视，异常邮件才进入人工处理。

## 使用方式

1. 在 `chrome://extensions` 开启开发者模式。
2. 点击“加载已解压的扩展程序”，选择本目录。
3. 点击扩展图标打开独立工作台。
4. 需要创建草稿时，通过右上角邮箱状态区连接或切换网易邮箱。
5. 批量流程仍为 `导入资料 → 核验待办 → 选择与排期 → 创建草稿`。

## v2.5 关键变化

- **邮件审阅不再是整屏弹窗**：审阅页成为真正的主工作区页面，不再使用覆盖整个应用的 portal 弹窗。
- **主界面改为邮件块**：每封邮件独立显示对象、收件人、主题和自动识别状态。
- **颜色 + 形状编码状态**：绿色圆形=自动通过，蓝色圆角方形=已人工确认，橙色菱形=需处理，紫色六边形=重复取舍。
- **邮件块可原地展开**：点击邮件块只展开正文摘要和问题标签，不打断当前浏览节奏。
- **只有异常/主动编辑才弹窗**：单封处理弹窗只服务于当前邮件，不再同时携带整批队列。
- **搜索/筛选不再自动打开第一封**：用户明确点击“处理 / 编辑”才进入深度操作。
- **确认并下一封只追踪异常**：处理完成后跳到下一封仍需人工介入的邮件，不再机械逐封打开。
- **响应式重新核验**：1366×611 与 820×700 的状态板和单封弹窗均纳入自动截图检查。

详细设计与业务原则见 `docs/UI-REFLOW-v2.5.md`。

## 架构边界

可见工作台由 `app.html / app.js / app.css / app-shell.css / ui-system.css / workflow-dialogs.css` 负责；网易邮箱页面仅运行 `executor.js` 执行真实写信和草稿保存动作。`background.js` 负责工作台与邮箱标签页之间的连接。
