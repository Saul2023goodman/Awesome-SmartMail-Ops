# NetEase Mail Draft Assistant v0.7.0

v0.7.0 重点：统一“联系人状态 + 标签”为 **联系人分类（Classification）**。

## 为什么重构

v0.6 的六个“状态”混合了不同语义：

- `未联系 / 已发送 / 已回复`：互动生命周期，互斥。
- `待跟进`：行动标记，可与任意互动阶段同时存在。
- `暂停 / 不再联系`：发送策略，应该直接控制能否进入批量发送。
- 自定义标签：学校、批次、方向、优先级等自由属性，可多选。

如果把这些都做成普通标签，会失去互斥约束和发送安全；如果继续拆成“状态筛选 + 标签筛选”，UI 和批量逻辑又会出现两套事实来源。

## v0.7 分类模型

用户只看到一套“分类”，内部保存类型：

1. **互动阶段（单选）**：未联系 / 已发送 / 已回复
2. **待跟进（标记）**：可与阶段并存
3. **发送策略（单选）**：正常 / 暂停 / 不再联系
4. **自定义标签（多选）**：例如第一批、重点、北师大、心理学

## UI 优化

联系人表由“状态列 + 标签列”合并成一个“分类”列：

- 上方显示当前分类 chips；
- 同一单元格内编辑阶段、待跟进、发送策略和自定义标签；
- 联系人筛选也统一成一个“分类筛选”，支持“任一 / 同时包含”；
- 常用分类会自动生成快捷 chip。

批量发送列表中：

- “联系人状态”改为“联系人分类”；
- 表格标签明确为“任务标签”；
- 筛选范围 = 联系人分类 + 任务标签的并集；
- 因而可以直接筛选 `已回复;重点`、排除 `暂停;不再联系`。

## 发送安全联动

- 联系人策略为 **暂停**：相关任务自动排除发送并显示拦截原因。
- 联系人策略为 **不再联系**：相关任务形成预检错误并自动排除。
- 批量“加入发送”不会绕过上述策略。
- 必须先在联系人分类中将策略恢复为“正常”，任务才可重新加入。

## 已发送同步

扫描已发送邮件只推进“互动阶段”：

- 未联系 → 已发送
- 已发送保持已发送
- 已回复不会被降级
- 待跟进 / 发送策略 / 自定义标签均不会被扫描覆盖

## 旧数据迁移

继续使用 `nmda.contacts.v1:*` 存储键，首次加载自动迁移 v0.6 数据：

- 未联系 → 阶段=未联系
- 已发送 → 阶段=已发送
- 已回复 → 阶段=已回复
- 待跟进 → 待跟进=true；阶段按是否存在发送历史推断
- 暂停 → 发送策略=暂停；阶段按发送历史推断
- 不再联系 → 发送策略=不再联系；阶段按发送历史推断

无需重新建立联系人库。

## 导出格式

联系人 CSV 现在导出：

`邮箱 / 姓名 / 互动阶段 / 待跟进 / 发送策略 / 自定义标签 / 已识别发送次数 / 最后发送时间 / 最后主题`

## 原有功能

保留 v0.6 的单封草稿、XLSX/CSV/JSON 批量导入、字段识别、附件中心、定时设置、顺序建草稿、已发送读取、联系人历史等功能。

> 插件只创建/保存草稿，不自动点击最终发送。
