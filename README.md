# NetEase Mail Draft Assistant v1.32.0 · TASK-HIERARCHY

这一版把导入后的信息重新按业务后果分级：**附件缺失属于阻塞项，参考总名单属于可选增强，自动分流/读取提示属于系统详情**。流程 2 首屏优先展示当前待办；已完成的导入动作压成工具栏；参考名单做出选择后自动降级；附件只有在成为当前最高优先级时才获得主按钮。

详见 `TASK-HIERARCHY-v1.32.md`。


网易邮箱网页版草稿辅助插件。主流程：**添加资料 → 处理待办 → 选择与安排 → 创建草稿**。插件只创建/保存草稿，不自动发送。

## v1.31.0

这一版把“参考总名单”从隐藏的可选资料提升为**导入阶段的上下文预检**：邮件导入后，系统主动说明上传总名单的收益，并要求用户明确选择“现在上传”或“本批次暂不添加”；它仍然是可选增强，不会被错误做成硬性依赖。

- **导入时主动提示参考总名单**：不再藏在“更多资料”；邮件导入后如果尚无总名单，步骤 1 保持当前状态，直到用户上传或明确跳过。
- **可选但不隐形**：跳过后基础批次查重仍继续工作；之后仍可补充，总名单只增强名单交叉核验、身份/院校上下文。
- **附件前置预检**：识别到附件要求时，提前建议一次选择文件夹/文件以便批量匹配；可以“稍后处理”，不会抢占收件人、重复等更高优先级待办。
- **待办完成后自动续接**：邮件类待办清零后直接出现“继续：添加附件（N）”或“继续：选择与安排”，不再要求用户退出检查页自己找下一步。
- **排期前只确认必要变量**：只让用户确认开始时间和同校间隔，并说明当前院校上下文来源，不暴露 scheduler 内部逻辑。
- **创建前结果预检**：汇总已选、定时、附件、排除数量，并再次明确“只创建 / 保存草稿，不自动发送”。
- **统一 Context Preflight 原则**：高收益可选上下文在最能减少返工的时点主动出现；允许明确跳过；任何上下文变化后依赖状态立即重算。

完整业务分析和设计规则见 `CONTEXT-PREFLIGHT-v1.31.md`。

## v1.30.0

这一版把 Review Canvas 继续收敛为 **Decision Canvas**：高频核心动作直接可见，系统技术证据退出用户主流程，需要比较多个候选时直接并排展示，而不是让用户逐个打开后靠记忆做决定。

- **“排除此封”改为直接操作**：移除只有一个选项的“更多”菜单；按钮固定在当前邮件工具栏中，但不悬浮、不遮正文，并保留可恢复机制。
- **彻底移除用户层“识别依据”**：解析线索、边界、置信度仍可作为内部判断数据使用，但不再要求用户理解 Parser 的工作过程。
- **重复邮件改为多篇同时预览**：2～3 封候选默认同屏并排；更多候选保持横向比较画布。每封同时展示主题、收件人、来源、正文和附件数量。
- **多选保留集合**：默认勾选信息更完整的一封，用户可在同一视图改为保留任意 1～N 封；未勾选项在确认后排除。
- **“查看内容”改为“编辑这封”**：比较本身无需跳转；只有确实要改某一封时才切换编辑对象，且已有保留勾选不会丢失。
- **候选收件人直接平铺**：当存在多个可用邮箱时，直接显示在收件人字段旁供选择，不再把它们藏在技术证据区。
- **去技术化比较信息**：重复候选不再展示“识别 85%/100%”等内部置信度，只保留来源、正文长度、附件等与用户取舍直接相关的信息。

完整分析与运行验证见 `DECISION-CANVAS-v1.30.md`。

## v1.29.0

v1.29 将邮件审阅重构为稳定 Review Canvas：长列表可搜索、顺序浏览，确认操作不再悬浮覆盖正文，并将流程定位与邮件编辑分离。

## v1.25.0

这一版把“查重”从“总名单核验的附属能力”提升为批量邮件自身的基础安全检查，并重新划分必需资料与可选增强资料。

- **无总名单也自动查重**：任务一生成即检查当前批次，同一收件人邮箱重复会直接进入“检查邮件”。
- **增加同名同院校疑似重复**：缺少邮箱时，用规范化姓名 + 可信院校作为次级证据；不会因为仅同名就误判。
- **重复确认绑定具体重复组**：确认记录不再是一个永久布尔值；修改收件人/院校或出现新的重复关系后，会重新要求核验，避免旧确认掩盖新风险。
- **总名单真正可选**：总名单只增强“名单外、尚未加入、联系人歧义、院校补全”等交叉核验，不再决定是否具备查重能力。
- **统一“联系人核验”面板**：同时展示当前批次查重、已有邮箱发送/草稿记录，以及可选总名单差异；用户不再需要理解三套技术来源。
- **历史记录只提示不阻塞**：已有发送或草稿记录可能是正常跟进，因此显示为安全参考；当前批次重复则必须明确确认后才能继续。
- **避免重复提示**：当前批次已经明确识别出的重复，不再额外叠加同义的“总名单同一导师多封邮件”阻塞。

整体业务模型与举一反三的依赖拆分原则见 `BUSINESS-FLOW-v1.25.md`。

## v1.24.0

这一版修复 v1.21 结构解析升级引入的“收件人前导区被上一封邮件尾部吞掉”回退。

- **恢复收件人识别能力**：同一复现资料从 v1.21~v1.23 的 `0 / 63` 恢复为 `58 / 63`，与 v1.19/v1.20 一致；剩余 5 封原资料本身没有可确定邮箱。
- **修复跨邮件所有权**：上一封的来源/备注仍会隔离，但遇到下一封明确收件人时立即停止 `consumedEndBlock`，不再越过下一记录邮箱。
- **支持带备注的邮箱行**：`📧 name@university.edu（请以官网为准）` 仍识别为明确收件人。
- **Markdown 身份标题优先**：`### Name — email@university.edu` 先按对象标题判断，不再被通用 Markdown 说明规则吞掉。
- **保留防串线**：来源字段中的邮箱仍不会成为下一封收件人；真正歧义的两个候选仍进入人工确认。
- **新增归属回归测试**：覆盖“说明 → 下一收件人 → 编号/标题 → Subject”、Markdown 标题邮箱，以及来源邮箱防串线。

完整根因与所有权模型见 `RECIPIENT-OWNERSHIP-v1.24.md`。

## v1.23.0

这一版重构“选择与安排”面板：院校不再作为用户必须维护的邮件字段，而是自动排程的后台参考。

- **修复 `A / B / C` 伪院校**：单字母、数字、批次、分组、类别和标签值不再作为院校。
- **院校证据改为保守策略**：优先使用总名单或明确院校名称；简称需要与高校邮箱对应；无法确认时保守错峰，不要求补填。
- **移除学校主表列**：选择表由六列缩减为“选择、收件人、主题、发送时间、结果”，不再诱导用户逐行维护内部排程数据。
- **院校差异不阻塞草稿**：总名单与导入来源不一致时，排程使用总名单，差异仅保留在按需查看的排程参考中。
- **排程文案面向任务**：去掉学校/分组数量、邮箱分组等内部描述，只说明已选、自动、已有、待排和时间冲突。
- **搜索与说明同步简化**：主表搜索聚焦收件人与主题；面板明确说明院校只用于同校错峰，不影响邮件内容。

完整业务判断和界面层级见 `SCHEDULE-PANEL-v1.23.md`。

## v1.22.0

这一版在邮件解析之前增加“资料用途分流”，解决多文件上传时名单、CV、研究计划等非邮件资料被误生成邮件任务的问题。

- **先分流再生成任务**：每组内容先判定为邮件、总名单、附件候选或暂不使用；只有“邮件”进入任务生成器。
- **名单自动进入核验资料**：带有姓名、邮箱、院校、批次/状态等字段且不含邮件主题/正文的表格自动作为总名单，不占邮件任务数。
- **CV 与申请材料进入附件候选**：DOCX、PDF、PPT、图片等材料可与邮件文件混合选择；它们进入附件池，但不会自动附到每封邮件。
- **未知资料默认不参与**：没有充分结构证据的普通文档或表格默认暂不使用，不制造缺收件人/缺主题/缺正文等伪阻塞。
- **单个文件失败不拖垮整批**：混合上传中某个文件无法读取时仅隔离该来源并显示提示，其余邮件继续处理。
- **取消“最像邮件”兜底**：完全没有邮件来源时停止在资料分流页，提示“未找到可确认的邮件资料”，不再强制启用一个猜测结果。
- **源级一次调整**：识别用途不对时，可把整组内容改为邮件、总名单、附件候选或暂不使用，无需逐行排除伪邮件。
- **职责彻底隔离**：任务数、待检查队列、自动推进、排程和草稿创建只读取邮件源；名单只参与交叉核验；附件只参与文件匹配。

完整根因、业务阻碍和分流状态模型见 `SOURCE-ROUTING-v1.22.md`。

## v1.21.0

这一版把解析从“每段单独贴标签”升级为完整的邮件结构序列，重点解决中文结束语、署名和邮件终点错位，并提高各组成部分的定位一致性。

- **修复截图错误**：`此致\n敬礼—` 后的破折号不再触发“未归类尾部”；下一段姓名会识别为署名，邮件终点落在姓名上。
- **支持跨段结束语**：`此致` 与 `敬礼` 位于不同 Word 段落、同段不同换行或与姓名同段时均可形成一个结束语结构。
- **位置与语义共同判断**：纯数字 `123` 位于主题标记后仍是合法主题，只有处在记录边界位置时才可能视为编号。
- **来源与业务字段支持跨行**：`Research source`、`附件清单`、`发送时间` 可作为独立标题，后续链接、文件名或时间继续归入同一字段。
- **降低正文误截断**：正文句子中的 `Many thanks ...`、`Best regards to ...` 不再因为包含结束语词组而提前结束邮件。
- **收件人歧义可见**：多个分数相近的邮箱候选不再静默任选，保留候选并进入真正需要人工判断的待确认。
- **解析依据与识别器同源**：界面不再另用一套简化正则猜标签，直接显示对象标题、收件人线索、主题、称呼、正文、结束语、署名、附言及已排除字段。
- **边界含义更准确**：结束语与署名分开，邮件终点指向最后一个实际写入草稿的块，而不是来源段或结束语段。

完整原因、结构模型和举一反三范围见 `PARSER-STRUCTURE-v1.21.md`。

## v1.20.0

这一版将正文解析从“落款后再取两行”的位置规则升级为统一的语义边界系统，重点解决来源、备注等辅助内容侵入草稿正文。

- **统一块角色分类**：Subject、称呼、正文、落款、签名、附言、来源、附件、定时说明、收件人线索、内部备注和下一记录使用同一个分类入口。
- **签名不再按固定行数猜测**：支持姓名、身份、院系、联系方式、个人网站等多行签名；遇到明确来源或内部说明立即结束正文。
- **同段混排也能切开**：落款、姓名和 `Research source` 即使位于同一 Word 段落或 HTML 文本块，也会分别判断。
- **明确元数据自动分流**：来源不写入正文；附件和定时时间会进入对应字段，不再既污染正文又丢失业务含义。
- **模糊内容安全降级**：落款后无法确认角色的文本先从正文隔离，并保留待确认原因，避免静默误删或误发。
- **跨记录防串线**：来源段中的邮箱不会再被下一封邮件误识别为收件人，来源段也不会成为下一封邮件的身份标题。
- **双层防护**：识别器生成正文时裁剪一次，任务生成前对“自动识别正文”再做一致性净化；人工编辑和明确表格正文不被擅自改写。
- **解析依据可解释**：原文中被隔离的段落以“已排除·来源/附件/说明”等标签显示，并展示隔离数量。

系统性设计、边界策略与覆盖案例见 `PARSER-SYSTEM-v1.20.md`。

## v1.19.0

这一版重点解决“事情已经完成，但界面仍要求再确认/再进入下一步”的重复操作。

- **确定性问题补齐即通过**：缺收件人、主题或正文时，补齐并通过字段验证后自动移出待处理。
- **一键主题不再要求全选确认**：填写同一主题后，每封邮件按当前事实重新判断；只缺主题的自动完成，真正有解析歧义的才继续待处理。
- **识别状态会随当前内容更新**：缺 Subject 等原因导致的旧低置信度不会在用户补齐主题后继续作为历史阻塞。
- **最后一个待办完成后自动推进**：有下一封就自动打开；缺附件就自动去附件区；全部完成就自动进入“选择与安排”。
- **干净批次直接进入下一步**：导入后没有阻塞时，无需再点“继续选择邮件”。
- **邮件内容成为检查区主视图**：收件人、主题、正文位于主要编辑区域；正文提供更大的完整编辑空间。
- **原文降级为“解析依据”**：默认按需展开，展示识别步骤、置信度、候选邮箱与原始块边界；只有存在真实解析歧义时自动展开。
- **批量确认只服务真正的人工判断**：缺字段邮件不再出现无意义的批量确认选择。
- **自动安排时间继续默认展开**：进入“选择与安排”后直接可用。

详细逻辑见 `UX-FLOW-v1.19.md`。

3. 选择“加载已解压的扩展程序”，指向该目录。
4. 打开网易邮箱网页版使用。
