# NetEase Mail Draft Assistant v2.6 · Review-first Mail Audit

v2.6 保留原有导入、识别、附件、总名单、查重、排期、联系人和草稿执行逻辑，重新定义“邮件审阅”这一步的职责：**先快速判断自动识别有没有出错；只有发现错误才进入修正。**

## 使用方式

1. 在 `chrome://extensions` 开启开发者模式。
2. 点击“加载已解压的扩展程序”，选择本目录。
3. 点击扩展图标打开独立工作台。
4. 需要创建草稿时，通过右上角邮箱状态区连接或切换网易邮箱。
5. 批量流程仍为 `导入资料 → 邮件审阅 → 选择与排期 → 创建草稿`。

## v2.6 邮件审阅重构

- **卡片不再展开第二层预览**：邮件块本身只承担状态识别、对象定位与异常提示；点击任意卡片直接进入单封审阅。
- **卡片防碰撞**：固定卡片高度、稳定网格行高、14px 横向间距 / 12px 纵向间距、取消 hover 位移，并使用 `contain` 隔离布局与绘制。
- **状态信息只出现一次**：例如缺主题只显示一个“缺主题”标签，不再同时出现“补主题 / 补主题”重复动作描述。
- **五类状态可直接筛选**：全部 / 自动通过 / 需处理 / 冲突重复 / 已确认。
- **弹窗默认是审阅器，不是编辑器**：打开后先显示收件人、主题、开头、结尾、附件五个核验点。
- **开头与结尾优先**：分别抽取称呼/第一段与收尾/署名，放在完整邮件之前并排展示，用于快速发现邮件边界识别错误。
- **完整邮件连续显示**：正文从头到尾只读展示，不需要进入编辑状态才能检查内容。
- **编辑降级为次级分支**：只有点击“发现问题，修正”才出现收件人、主题、正文输入框；修正后可返回审阅重新确认。
- **确认逻辑更安全**：缺少收件人、主题或正文时禁止直接确认；边界、称呼、落款等不确定问题可在完整审阅后人工确认。
- **处理完成不自动跳离审阅页**：确认一封后返回状态板；“确认无误，下一封”只跳到下一封仍需人工处理的邮件。

详细业务与设计原则见 `docs/UI-REFLOW-v2.6.md`。

## 自动 UI QA

```bash
python3 qa/ui_audit.py
# 或
./qa/run_qa.sh
```

QA 使用真实 Word + Excel + PDF 测试资料，并覆盖 1440×900、1280×800、1100×760、920×720、820×700、1366×611。v2.6 额外加入：

- 12 卡片压力布局，自动计算卡片矩形是否发生重叠；
- 1366×611 邮件状态板；
- 1366×611 / 820×700 只读审阅弹窗；
- “发现问题，修正”次级编辑模式；
- 弹窗与卡片区嵌套滚动、越界、控件碰撞检查。

当前 v2.6 基线：**静态/架构检查 PASS，真实导入 PASS，来源角色 20 项回归 PASS，阶段隔离 PASS，12 卡片碰撞检查 PASS，所有自动审阅截图 P0 = 0、P1 = 0。**
