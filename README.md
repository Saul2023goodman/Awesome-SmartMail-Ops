# NetEase Mail Draft Assistant v1.9.0

v1.9.0 把“定时发送时间”从单个字段升级为批量任务中的学校级排程规则引擎。扩展仍然只创建并确认保存网易草稿，不自动点击最终发送。

## 核心流程

导入任务 → 校验 / 人工修正 → 批量任务选择 → 智能排程 → 创建草稿

智能排程只处理“已选择 + 预检通过”的任务，筛选仍然只影响视图。

## 默认业务规则

- 同一学校每轮最多 1 位；
- 下一轮默认间隔 7 天；
- 不同学校可以进入同一轮；
- 首轮开始时间由用户设置，进入新批次时自动给出一个未来整点作为起点；
- 默认保留导入或手工设置的定时时间；
- 重新生成排程只刷新由系统自动生成的时间。

以上参数均可在“批量任务 → 智能排程”中调整并保存偏好。

## 学校 / 机构识别

`学校 / 机构` 已成为 Universal Import Engine 的一级可选字段，支持学校、院校、机构、University、Institution、Affiliation 等表头。

Word 邮件原语识别会优先从类似 `Daniel Lock — Loughborough University London` 的身份标题中提取学校。若没有可靠学校信息，排程器不会猜正文中的学校（正文可能包含发件人自己的学校），而是退回收件邮箱域名作为分组依据，并在 UI 中明确标记“域名兜底”。

批量任务表中的“学校 / 分组”可直接人工修改，修改后下一次排程立即按新分组计算。

## 时间来源

每条任务区分：

- `导入时间`：来源文件本身带有定时时间；
- `手工调整`：用户在批量任务表中直接修改；
- `自动排程`：规则引擎生成；
- `未定时`：当前没有时间。

“清除自动排程”只移除自动生成的覆盖值；原始导入时间会重新显现，手工/导入信息不会被无条件删除。

## 规则冲突

如果“保留已有定时”导致同一学校在同一轮中超过限制，系统会显示冲突警告，而不是静默覆盖人工决定。用户可：

1. 直接修改对应行的定时时间；或
2. 关闭“保留已有定时”后重新生成整个已选任务集的排程。

## 验证

- `scheduler.js` 独立规则引擎；
- 默认规则回归：A 学校两位分别进入第 1 / 第 2 轮，B 学校首位可与 A 学校首位同轮；
- 已有人工时间会占用对应学校轮次；
- 学校缺失时按邮箱域名稳定分组；
- 所有 JS 通过 `node --check`；
- Manifest 版本为 1.9.0；
- UI DOM ID / 静态引用完整性检查通过。
