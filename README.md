# NetEase Mail Draft Assistant v1.10.0

v1.10.0 新增“总套磁名单交叉核验”。总名单被定义为 Reference Roster（参考主数据），不是待发送任务表：它用于身份对齐、院校补全、覆盖检查、重复撰写检查和人工校正证据，不会因为导入总名单而增加草稿任务数量。

## 业务流程

总套磁名单（候选池 / 主数据）
→ 实际已撰写邮件（执行子集）
→ 交叉核验与信息补全
→ 人工只处理真实差异
→ 附件校验
→ 批量任务选择
→ 学校级智能排程
→ 创建并确认保存草稿

“总名单数量”和“实际已撰写邮件数量”允许不同。未撰写的总名单导师只是候选池中尚未进入执行层的记录，不会被视为导入错误。

## 交叉核验匹配优先级

1. 精确邮箱：100 分，最高可信身份锚点；
2. 姓名 + 学校：94 分；
3. 唯一姓名：82 分，只在总名单中该姓名唯一时使用；
4. 多个同名候选：不自动绑定，进入人工确认；
5. 无匹配：默认仅提示“名单外邮件”，可开启严格模式要求人工确认。

## 最大化利用总名单

- 当前邮件学校为空 + 高置信度匹配 → 自动补“学校 / 机构”；
- 当前邮件缺邮箱 + 姓名/学校唯一匹配 → 总名单邮箱进入人工校正候选，不静默修改收件人；
- 当前学校与总名单学校冲突 → 阻塞并要求确认；
- 同一总名单导师对应多封当前邮件 → 标记“疑似重复撰写”，阻塞交接；
- 总名单中的批次、状态、优先级、分类、备注会作为参考元数据保留，不自动污染当前任务分类；
- 总名单补出的学校直接进入 v1.9 学校级排程，因此同校 7 天间隔规则可以利用主数据而不是只依赖邮箱域名。

## UI

“导入任务”中的主来源仍然是实际邮件来源。其下新增“总套磁名单 · 可选参考源”，两者职责分离：

- 邮件来源 → 生成 MailTask；
- 总套磁名单 → 生成 Reference Roster；
- 总名单不增加任务数。

载入后出现“总名单交叉核验”卡片，显示：

- 总名单记录数；
- 当前已撰写邮件数；
- 已对齐；
- 总名单尚未撰写；
- 名单外邮件；
- 身份 / 院校 / 重复差异；
- 自动补学校数量；
- 缺邮箱时可提供候选的数量。

默认开启“自动补空缺学校”。“严格模式”默认关闭，因此总名单仍在变化时，名单外邮件只提示、不阻塞；身份歧义、院校冲突和疑似重复撰写始终需要处理。

## 批次生命周期

Reference Roster 是当前批次的独立参考源：替换邮件来源时会保留总名单，方便连续核验不同邮件批次；只有点击“重新开始”或“移除总名单”才会清除参考源。更换总名单会使此前针对旧总名单做出的人工核验确认失效，防止错误复用。

## 默认智能排程

继续沿用 v1.9：

- 同一学校每轮最多 1 位；
- 下一轮默认间隔 7 天；
- 不同学校可以同轮；
- 默认保留导入/手工定时时间；
- 自动排程只处理已选择且预检通过的任务。
