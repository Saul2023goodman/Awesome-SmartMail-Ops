# NetEase Mail Draft Assistant v1.0.3

本版本是一次“产品逻辑减法”。目标不是增加更多开关，而是让每个用户意图只有一个明确入口：

- **检索 / 分类筛选**：只负责找到任务，不改变执行集合。
- **勾选**：是批量执行的唯一事实来源。
- **分类**：只负责联系人/任务组织与业务规则。
- **创建草稿**：只执行已勾选、预检通过的任务。
- **执行错误**：立即停止，优先避免串稿。

插件仍然只创建草稿，不自动发送。

## 主要删减

### 批量任务

附件来源也从“三类”收敛为两个概念：**任务附件**（可选择文件或目录）和 **公共附件**（每封都附加）。

删除：
- “全部已纳入任务 / 仅当前检索筛选结果”执行范围选择。
- “单封失败后继续”开关。
- 分类筛选“包含任一 / 同时包含”下拉。
- 自动识别成功时常驻显示的整套字段映射控件。

改为：
- 多个“包含分类”固定为 **AND（同时满足）**。
- 字段自动识别成功时只显示识别摘要；需要时点“校正字段”再展开映射。
- “选择当前结果 / 取消当前结果 / 清空选择”。
- 表格第一列统一叫“选择”。
- 开始按钮实时显示“创建 N 封草稿”。
- 真正执行时只读取勾选状态；筛选条件不会隐式影响执行范围。
- 检索/筛选不再跨批次持久化；导入新文件时自动清空，避免旧条件把新任务“藏起来”。
- 导入新任务表会清空上一批次的附件池与手动附件匹配，避免跨批次误挂附件。
- 任一执行错误自动停止。

### 单封草稿

删除：
- “设置定时发送”复选框。
- “填入后自动存草稿”复选框。
- “只打开写信”。

改为：
- 定时时间留空 = 普通草稿；填写时间 = 自动设置定时。
- 点击“创建草稿”后始终自动保存。
- 批量表也不再使用“是否定时”作为独立字段；**定时时间本身是唯一事实来源**。

### 联系人

删除：
- “打开已发送 / 打开草稿箱”。
- “读取已发送 / 读取草稿箱”两套重复操作。
- 联系人分类“匹配任一 / 同时包含”下拉。
- “同步当前批量名单/分类”按钮。

改为：
- 一个“同步邮箱历史”同时读取已发送和草稿箱。
- 多个联系人分类筛选固定为 AND。
- 导入批量任务时自动建立新的“未联系”联系人；任务分类不会自动写进长期联系人分类。
- “发送策略”在 UI 文案中统一为“联系策略”。

## 为什么这样设计

旧版本中多个控件会重复表达同一意图。例如用户已经通过筛选找到 5 个任务、又通过复选框选中其中 3 个，底部仍需要再决定“全部纳入 / 当前筛选”，这会产生第三套执行范围规则。更危险的是，屏幕当前显示的结果和真正执行的集合可能不同。

v1.0.3 采用单一事实来源：

```
检索 / 分类筛选
       ↓
找到要处理的任务
       ↓
勾选 / 批量选择
       ↓
已选择任务集合（唯一执行集合）
       ↓
创建草稿
```

因此“看什么”和“做什么”被明确分离。

## 联系人分类模型

联系人仍然保留内部语义：
- 互动阶段：未联系 / 已发送 / 已回复
- 待跟进
- 联系策略：正常 / 暂停 / 不再联系
- 自动分类：有草稿
- 自定义分类

UI 统一叫“分类”，但底层不把关键业务状态退化成普通自由标签。

## 安装

1. 解压 ZIP。
2. Chrome 打开 `chrome://extensions/`。
3. 开启“开发者模式”。
4. 点击“加载已解压的扩展程序”。
5. 选择 `netease-mail-draft-assistant-v1.0.3` 文件夹。
6. 刷新网易邮箱页面。

## 升级说明

- v0.9.x 联系人数据继续沿用。
- 旧单封表单中若“设置定时发送”未勾选，升级后会清除其旧的定时时间，避免误定时。
- 新批量导入只以“定时时间”判断是否定时；旧“是否定时”列不再作为独立控制字段。



## v1.0.3 保存草稿协议

每一封邮件都执行同一条强制流程：

`填写收件人/主题/正文 → 附件 → 定时 → 点击“存草稿” → 确认进入草稿状态 → 下一封`

- “存草稿”不是可选动作，每封都必须主动点击。
- 点击后必须确认网易已经接受保存并进入草稿状态。
- 找不到“存草稿”按钮、点击失败或保存状态无法确认时，当前封标记失败并立即停止整个批次。
- 不允许在“仅点击但未确认保存”的情况下继续下一封，避免串稿或丢稿。

## v1.0.1 修复

- 修复导入后 `setMappingEditorOpen is not defined`。
- 恢复字段映射编辑器的展开/收起控制器。
- 恢复“校正字段 / 收起字段”按钮点击事件与 `aria-expanded` 状态。


## v1.0.3 存草稿定位修复

- 根据网易真实 DOM，优先定位 `span.nui-btn-text` 中的“存草稿”，再向上解析其 `[role="button"]` 父按钮。
- 不再依赖 `_mail_button_*` 动态 ID。
- Compose root 内找不到时自动回退到当前网易页面 document，兼容顶部 toolbar 位于 Compose 内容根节点之外的布局。
- 点击后仍强制等待路由进入 `type: draft`，确认保存成功后才允许下一封。
