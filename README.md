# NetEase Mail Draft Assistant v1.8.0

v1.8.0 重构了“导入任务”的批次生命周期，并对整个工作台做了一次产品级减法。

## 根因修复：为什么“清空”后数据会回来

旧实现能清空 `batch.dataset / batch.tasks / taskEdits / attachments`，但解析 Word、ZIP、目录等工作是异步的。旧批次没有 session / generation 标识，因此可能出现：

1. 开始解析大文件；
2. 用户点击“清空本批次”；
3. 当前 UI 和数组被清空；
4. 旧解析 Promise 随后完成；
5. 旧结果再次调用 `applyImportedDataset()`，把任务重新写回。

v1.8 为每个批次增加 `sessionId`。开始新导入或重新开始都会使上一 session 永久失效。任何异步解析完成后，必须先证明自己的 token 仍属于当前 session，才有资格写入 UI / batch state。旧任务即使后台完成，也会被直接丢弃。

## “重新开始”现在真正重置什么

一次操作会清除：

- 当前数据源与数据集；
- 内容集合及自动识别结果；
- 字段映射与识别模板建议状态；
- MailTask 列表；
- 人工校正、确认、排除状态；
- 任务附件、公共附件、附件人工匹配；
- 导入预览与异常队列；
- 批量检索、分类筛选、临时批量分类输入；
- 当前导入状态和交接状态；
- 仍在后台运行的旧解析结果的写权限。

联系人历史是独立的持久 CRM 数据，不属于“当前批次”，因此不会被“重新开始”删除。

## 去除导入阶段的持久副作用

旧版在“识别/校正”阶段就会自动把收件人写入联系人库。这会导致用户仅仅试导入一个文件，联系人库就已经被修改。

v1.8 改为：

- 导入与人工校正阶段只生成临时 MailTask；
- 仍会读取现有联系人策略用于重复联系/暂停等判断；
- 只有用户明确点击“进入批量任务”时，才登记本批次中新出现的联系人。

因此导入工作台成为真正可丢弃、可重新开始的 staging area。

## UI 重构

主导航统一为：

- 单封草稿
- 导入任务
- 批量任务
- 联系人

导入页不再显示重复的五步流程胶囊。主要结构收敛为：

1. **选择来源**：文件、多文件、文件夹、ZIP、粘贴；
2. **识别结果**：识别总数、自动通过、待人工确认、其他阻塞；
3. **异常处理中心**：只处理机器真正不确定的记录；
4. **附件**：只在任务需要时处理；
5. **完成导入**：通过门禁后进入批量任务。

“识别诊断与高级映射”和“任务抽查”继续保留，但退出默认主流程。

## 同类稳定性修复

- 修复附件候选评分中的未定义标识符 `return65`，避免特定相似文件名触发 Runtime ReferenceError；
- 清理联系人对象中的重复 `email` 字段定义；
- Importer 内部版本统一为 1.8.0；
- 清空操作会同时重置筛选、预览、异常处理 UI，而不是只改数组；
- 新来源会自动使旧解析 session 失效，所以连续快速选择不同文件也不会发生结果串批。

## 安全边界

- “重新开始”不会删除联系人历史；
- 批量运行期间不能重新开始；
- 导入阶段不会操作网易写信页面；
- 只有批量任务中明确勾选的任务才会创建草稿；
- 创建每封后仍必须点击并确认网易“存草稿”成功，任何执行错误立即停止。
